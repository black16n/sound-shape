# 声音的形状 —— 项目完整方案与分工文档

> 首届郑轻中源黑客松 · 版本 v2（声纹平台版）
> 一句话：**给听不见的人，做一盏"认得出声音"的灯——你教它认什么，它就认什么。**

---

## 0. 项目定位（先统一认知）

| 项 | 内容 |
|---|---|
| 一句话 | 你教它认什么声音，它就用光告诉你什么声音来了 |
| 目标用户 | 听障人士（以及需要"声音→视觉"提示的任何人） |
| 核心差异化 | **不是音量灯**：音量灯只会亮，我们能"认出"具体是哪种声音，而且能**学你家的声音** |
| 产品形态 | 软硬结合：ESP32 声纹识别硬件 + 网页可视化大屏 |
| 当前阶段 | **纯本地、离线 MVP**（云端/UUMit 变现留作下一步） |

**核心转变（相比第一版）**：
- ❌ 砍掉"水开了"等固定预设声音
- ✅ 升级为"**声纹平台**"：用户自己录、自己训练、自己命名，我们只提供几个样例当种子
- ✅ 识别规则从"多分类器"简化为"**模板匹配**"（比相似度，命中最高）

## 1. 功能清单（具体到可验收）

### 功能 A：样例声纹（开箱即用）【软件/算法】
- 预置 3 个样例模板：**门铃、敲门、婴儿哭**
- 用户不训练也能直接用这 3 个
- 验收：烧录后，播放预录的样例声音，能正确触发对应提示

### 功能 B：用户自训练声纹（核心）【软件/算法 + 硬件】
- **长按按键 10 秒** → 进入训练模式
- OLED 引导：录 N 次（建议 3~5 次）→ 取平均 → 命名 → 保存
- 声纹存 ESP32 本地 NVS，断电不丢
- 验收：现场录一个新声音（如"拍两下手"），能训练成功；断电重启后仍能识别

### 功能 C：实时识别【软件/算法 + 硬件】
- 持续监听 → 检测到声音 → 提取指纹 → 与所有已存模板比相似度 → 命中最高且超阈值 → 触发
- 触发后：OLED 显示模板名 + 闪烁节奏（单色屏用节奏代替颜色）
- 去抖 + 冷却，防止连环误报
- 验收：播放门铃声 → 灯/屏正确响应；播放无关声音 → 不误触发

### 功能 D：硬件交互【硬件】
- 按键：短按（切换模板/确认）、长按（进训练）
- OLED：待机呼吸态 + 训练引导 + 识别结果
- 灯带（如有）：识别触发时的视觉提示（可选加分项）

### 功能 E：网页可视化大屏【设计/前端】
- 展示：平台概念、声纹库列表、识别历史、训练引导
- 用途：路演投屏，讲清楚"平台"这个故事
- 验收：浏览器打开能看、能演示、能截图进 PPT

## 2. 技术架构

```
┌─────────────┐   I²S   ┌──────────────┐   I²C   ┌─────────────┐
│  INMP441    │────────▶│  ESP32-S3    │────────▶│  0.96 OLED  │
│  麦克风     │  音频流  │  FFT+声纹比对 │  显示    │  (结果/引导) │
└─────────────┘          │  NVS存指纹    │          └─────────────┘
                         │              │
                         │  GPIO(按键)   │
                         └──────┬───────┘
                                │ 长按=训练/短按=切换
                         ┌──────▼───────┐
                         │  五色按键     │
                         └──────────────┘

        （当前阶段：全部本地，无网络）
```

**技术选型**：
| 层 | 技术 | 说明 |
|---|---|---|
| 采样 | ESP32 I²S 驱动 | 16kHz，INMP441 |
| 频谱 | arduinoFFT 库 | 256 点 FFT |
| 特征 | 峰值频率 + 能量比 + 节奏 | 轻量，本地算 |
| 比对 | 余弦相似度 | 模板匹配 |
| 存储 | Preferences (NVS) | 断电不丢 |
| 显示 | U8g2 库 | OLED 128×64 |
| 前端 | 纯 HTML/CSS/JS | 单页大屏，无后端 |

## 4. 声纹训练交互流程（给成员2+1 照着实现）

```
待机态（呼吸"静"）
    │
    ▼ 长按按键 10 秒
进入训练模式
    │ OLED 显示 "训练模式 录音中..."
    ▼ 开始录第 1 次（提示语）
录第 1 次 → OLED "第1次完成 再来1次"
    │ 短按 = 继续录下一次
    ▼ 录第 2、3 次（建议共 3~5 次）
录完 → OLED "取平均中..."
    │
    ▼ 自动取平均，得到标准指纹
命名 → OLED "已保存:模板X"
    │
    ▼ 存 NVS
回到待机态
```

**关键交互规则**：
- 长按 10 秒 = 进入/确认训练
- 短按 = 触发下一次录制 / 切换模板
- 每次录制：检测到声音能量上升→下降，自动截取"声音片段"
- 录 3~5 次取平均，指纹才稳定

## 5. 识别规则（最终版，简化后）

核心就一句话：**模板匹配**（不再是多分类器）。

```
监听循环（每 100ms）：
  1. 算 RMS，< 阈值 → 待机呼吸灯
  2. 检测到声音 → 提取指纹（峰值频率+能量比+节奏）
  3. 与所有已存模板逐个算相似度
  4. 取最高分，若 < 阈值(如0.7) → 忽略
  5. 命中 → 去抖(1s) + 冷却(2s) → OLED显示模板名+闪烁
```

**为什么简单可靠**：用户录的时候，已经把"什么是门铃"的定义交给了用户，我们只需"比像不像"，不用"猜是什么"。

## 8. 风险与兜底

| 风险 | 兜底方案 |
|---|---|
| 现场无灯带 | 单色 OLED 用闪烁节奏代替颜色 |
| 训练现场录不好 | 预置 3 个样例兜底，现场也能演示 |
| 麦克风误触发 | 阈值 + 去抖冷却，demo 时保持环境安静 |
| 硬件烧录失败 | ESP32 有 2 块备用 |
| 时间不够 | 砍功能保核心：训练 + 识别是底线，前端可降级为 PPT 截图 |
